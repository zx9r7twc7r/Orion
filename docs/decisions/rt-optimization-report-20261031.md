# RT 性能优化报告（2026-10-29 ~ 10-31）

> 本报告覆盖这一轮完整的性能排查：从"分箱延迟材质"立项，到最终落地 **payload 124 B → 64 B**。
> 所有数字都是**同局 A/B**（`ORION_PERF_ABLATION=alt:` / `ORION_SER_LADDER` / `ORION_SHARC_AB`，
> 相邻 60~120 帧窗口逐对相减）。**跨局不可比**：同一份代码 base 在不同局能差 2×
> （实测见过 15.09 / 16.30 / 18.45 / 22.03），这是本轮的硬约束，也两次避免了错误结论。

---

## 一、结论摘要

| 项 | 结果 | 性质 |
|---|---|---|
| **payload 瘦身** | 124 B → **64 B（−48%）** | ✅ 落地，用户实机反馈"明显更流畅" |
| **SER pin 5 → 6** | 0.52 ms（trace 3.2%） | ✅ 落地，零画面影响 |
| **emissive 无损跳过** | 理论 ~1 ms | ✅ 落地，观感逐位不变 |
| 分箱延迟材质 | 终止（SER 已做完，手工选 key 反而慢 0.24 ms） | ❌ 否定 |
| 次级 mip+2 | 1.43 ms 但室内变亮 | ⚠ 撤回，改 opt-in |
| 反射 tMax 96 | 1.85 ms 但反射变天空 | ⚠ 撤回 |
| OMM 2 态 | 0.00 | ❌ 否定 |
| SHaRC | 净亏 1.41 / 4.21 ms | ❌ 否定（结构性） |

**净收益**：SER 0.52 ms 是干净可测的；payload 的收益**没有严格量化**（无法同局 A/B，
编译期常量），只有用户体感与"payload 已贴着驱动编译器承受边界"的旁证（见 §5 的 LLVM OOM）。

## 二、trace 成本归属（判据基线）

### 2.1 三段分解（`alt:0,2,3`，base 17.51）

| 臂 | trace | Δ |
|---|---|---|
| base | 17.51 | — |
| noGlossy | 11.22 | −6.29 |
| noGi | 11.49 | −6.02 |

主射线 5.03 + 反射 6.29 + GI 6.02 = 17.34 ≈ 17.51 ⇒ **三项可加，无大块共享下游**。

### 2.2 SER 阶梯（`ORION_SER_LADDER=1`，191 窗口）

| 档 | trace |
|---|---|
| SER off | **28.05** |
| mode 1 | 15.66 |
| mode 4（手工 instance-class key） | 16.26 |
| mode 5（原 pin） | 16.02 |
| **mode 6（新 pin）** | **15.50** |

- **SER 价格 = 12.04 ms（42.9%）**，36/36 周期全胜。
- **mode 4 就是"手工分箱 key"，比 driver-picked 的 mode 5 慢 0.24 ms** ⇒ 手工分组在本场景是负的先验。

### 2.3 材质求值内部（总上界 7.45 ms）

| 项 | 量 | 口径 |
|---|---|---|
| POM 自阴影 | 1.12 | 干净（纯采样带宽） |
| albedo 采样 | 1.43 | 干净 |
| emissive 精确纹素 | ~1.13 | 含路径污染 |
| POM 面 normal 重采 | ~1.02 | 含路径污染 |
| 顶点解包 / TBN / LabPBR 数学 | ~2.75 | 未拆 |

- **POM 主 march 只值 0.12 ms**（`noPom` 1.29 − `noPomSelfShadow` 1.17）；钱全在自阴影 4~16 次双线性采样。
- **算术优化无效**：把采样边界计算提到循环外，Δ 1.17 → 1.12（噪声内）。

### 2.4 非材质内部（总 9.24 ms，五臂局）

⇒ 反射的钱几乎全在材质求值；GI 的钱主要花在弹射遍历。两者在 2.1 里看着对称，实为两件事。

## 三、已落地

### 3.1 payload 瘦身（主要成果）

| 阶段 | 改动 | payload | 结果 |
|---|---|---|---|
| 原始 | 21 字段 | 124 B | — |
| 1 | 删玻璃链 10 字段 | **68 B** | ✅ 用户"明显更流畅" |
| 2 | `albedo` vec3 → unorm8x4 | **64 B** | ✅ 无损 |
| 3 | `normal` → 八面体 2×16 | 56 B | ❌ 全屏黑，回退 |

玻璃链退化为**单片近似**（单片正确、多层叠加偏淡），符合"玻璃要重做"的计划。

### 3.2 SER pin 5 → 6

`mode 6 = mode 1 + DISTANCE_ONLY 走 rgen 侧查询`。像素安全（射线、flags、cull mask 完全相同，
只差重排 key 与查询侧）。⚠ 场景相关：10-12 的高压场景（rt 33.64）曾是 mode 5 更快，
回退只需把两行改回 `5u`。

### 3.3 emissive 无损跳过

`specularSample.a` 精确等于 1.0 时，参与双线性的 4 个纹素必然全是 1.0 ⇒ 中心纹素必为 255
（非自发光）⇒ 那次 `texelFetch` 白做。非发光方块占绝大多数，多数命中都能省。

### 3.4 其他

- POM 自阴影采样边界外提（严格等价，0 收益，代码更清楚）；
- 消融档 17-33（17 个探针），生产档 0 逐像素零变化；
- `docs/decisions/rt-cost-attribution.md`（判据基线）+ 三份交接文档。

## 四、被否定的方向（附证据，不要重试）

| 方向 | 证据 |
|---|---|
| **分箱 / 排序延迟材质** | SER 已把同一件事做完（材质成本 −60%）；mode 4（手工选 key）慢 0.24 ms；NVIDIA 官方把"按材质排序"列为被 SER 取代的旧步骤；论文主收益是 out-of-core 纹理（我们是常驻图集） |
| **BVH 侧（CLAS/Morton/分块）** | 遍历只占 1.09 ms / 7% |
| **减射线数**（tierHalf/rrGi/ao2of4/shadow1of2/march1） | 全部 ±2% |
| **材质算术优化** | hoist 后 1.17→1.12 |
| **OMM 2 态强制** | 0.00（我们的 alpha cutout 是二值，4 态里没有 unknown 态） |
| **SHaRC** | block=5 净亏 1.41；block=3 净亏 4.21；query 收益恒为 0（两次 −0.05 / −0.01），命中率仅 11.7%（2 跳 GI）。结构性无效 |
| **次级 mip+2** | 1.43 ms 真实，但 mip 平均化把贴图亮部扩散 ⇒ 室内/无光环境抬亮，撤回 |
| **反射 tMax 96** | 1.85 ms 真实，但 96 格外反射回落天空色 ⇒ 整体抬亮，撤回 |
| **payload +64 B 填充探针** | 触发驱动 SPIR-V 编译器 **LLVM OOM**（36 分钟后 NTSTATUS 0xC0000409） |

## 五、工程教训（本轮踩到的坑）

1. **加消融档必须同步三处**：`PERF_L10_ABLATION_STAGE_COUNT`、两处 `% N`、rgen 的
   `perfL10Stage()` clamp 上限。漏第三处 ⇒ 新档被静默折成上限值（本轮档 31 落到 30，
   量出来的是 noMatNoGi 的 7.64，差点当成结论）。
2. **一次只改一个字段**。`normal` + `albedo` 同时压缩导致全屏黑，无法区分元凶，白费一轮。
3. **`Copy-Item` 恢复源码会保留备份的旧 mtime** ⇒ 构建脚本判"未过期"不重编 ⇒
   部署的仍是坏版本 SPV（审计报成"漂移 5"）。回退后必须 `touch`。
4. **跨局不可比**。stationary 场景 base 波动 15~22 ms，比要测的量还大。只用同局 A/B。
5. **"收益 > 1 ms" ≠ "可以上线"**。亮度类副作用在帧时间上完全看不出来，必须在实机上单独确认。
6. **正则改代码要防注释**。复合写正则缺行首锚定，把注释里的 `payload.albedo *= 透射色`
   当成代码，跨行吞掉后续语句。
7. **payload 已贴着驱动编译器的边界**（+64 B 即 OOM）⇒ 任何增大 payload 的改动都要谨慎。

## 六、遗留与建议

| 项 | 说明 |
|---|---|
| **玻璃重做** | 当前单片近似。重做时不要恢复那 10 个字段（56 B），应走「独立 payload location=1」或「per-ray SSBO」，目标 opaque 侧 < 50 B |
| `normal` 八面体 | 收益 8 B，未定位失败原因（14 处写点需逐个核对）。优先级低 |
| `emission` → RGBE | 收益 8 B，HDR 编码风险中 |
| **SHaRC 重开前提** | `giBounces ≥ 3` 且必须同局实测；2 跳下结构性无效 |
| **注释清理的代价** | 全仓注释已删（121 shader + 66 Java）。建议补回三类：payload 字段语义、玻璃退化决定、消融档编号约定 |
