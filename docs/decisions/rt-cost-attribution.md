# RT 成本归属：每一毫秒在哪（2026-10-30 实测基线）

> 目标：给 `trace` 相位一个可复算的归属表，**避免重复投入已被实测否定的方向**。
> 所有数字都来自同局 A/B（`ORION_PERF_ABLATION=alt:…`，相邻 60 帧窗口逐对相减），
> 不用跨局对比——跨局的场景漂移可达 2×（同一份代码 base 在 16.3~25.1 之间摆动）。
>
> 状态：**已落地一项（次级 mip+2，默认开）**；其余方向全部实测为 0 或负收益。

---

## 1. 一句话结论

`trace` 里 **材质求值占 43%**，剩下 57% 里最大的一块是**主射线的固定成本 8.85 ms**
（不是遍历可调项、也不是阴影/AO 的射线数）。可落地的优化只有一项：
**次级命中 mip+2 = 1.43 ms**，已设为默认。

排序 / 分箱 / BVH 重排 / 减射线数 / 材质算术优化 / OMM 2 态——**全部实测 ≈0 或负**，
证据见 §7，不要重试。

## 4. 材质求值内部（总上界 7.45 ms）

| 项 | 量 | 口径 |
|---|---|---|
| **POM 自阴影** | **1.12** | 干净（纯采样带宽） |
| **albedo 采样** | **1.43** | 干净（albedo 不改射线方向） |
| emissive 精确纹素 | ~1.13 | 含路径污染，偏大 |
| POM 面 normal 重采 | ~1.02 | 含路径污染，偏大 |
| 未拆 | ~2.75 | 顶点解包 / TBN / LabPBR 数学 / 分支 |

- **POM 主 march 只值 0.12 ms**（`noPom` 1.29 − `noPomSelfShadow` 1.17）——视差本身几乎免费，
  钱全在自阴影那 4~16 次双线性采样（每步 4 次 `texelFetch`）。
- **算术优化无效**：把 `textureSize` / 纹素边界的重复计算提到循环外后，Δ 从 1.17 → 1.12，
  在噪声内 ⇒ 这块是纯采样带宽，只能减采样数。
- **外观会驱动路径**：把 roughness 换成常量 0.5（`noLabPbrMath`）后 `trace` 从 16.30 → 9.91
  （**−39%**）。这不是算术的价格，而是"反射射线从打得很远变成散射在近处"。

## 7. 被否定的方向（带证据，不要重试）

| 方向 | 证据 |
|---|---|
| **分箱 / 排序延迟材质** | SER 已把同一件事做完（−60% 材质成本）；手工选 key（mode 4）比 driver key 慢 0.24 ms；官方 SER 博客明说"不再需要排序阶段"；论文收益来自 out-of-core 纹理，我们是常驻图集 |
| BVH 侧（CLAS/Morton/分块/重排） | 遍历只占 1.09 ms / 7%；Morton 重排曾使 meshSec 954→3 |
| 减射线数（tierHalf / rrGi / ao2of4 / shadow1of2 / march1） | 全部 ±2%（成本由"命中分布"决定，不由数量） |
| 材质算术优化 | A 阶段实测 1.17→1.12，噪声内 |
| 反射 tMax 截断 | 有效（1.95）但画面会空；原因是**打空的射线要遍历整个 BVH**，不是"打到远处几何" |
| OMM 2 态强制 | **0.00**（我们的 alpha cutout 是二值，4 态里没有 unknown 态） |
| OMM 细分级别提高 | 同上，二值 alpha 在 level 4 已精确 |
| BLAS/instance 合并（降重叠） | 收益未证实，且会破坏 section 级 refit（asCreateN −72% 靠它） |

## 8. 唯一剩下的方向：B「payload 瘦身」

`HitPayload` 21 字段，其中**玻璃链专用占 56 B（≈45%）**：
`prevOffset×3 / lastGlassFaceT / glassFaceBudget / glassInside / glassEntryT /
transmittanceAccum / glassSurfaceWeightAccum / glassBlendAlpha`。

不能搬 SSBO：玻璃 anyhit 每穿一层都要累加，搬显存是每层一次往返，大概率更慢。
干净的路是 **B2：玻璃用独立 payload（location=1）**，opaque 那套瘦到 ~68 B。

前置（必须先做，30 分钟）：临时删掉玻璃字段、不追求画面正确，只量 `trace` 变化。
若收益 ≤1 ms 即终止；>1 ms 再投入 B2（一天量级，且玻璃路径有过 GPU 挂死先例，要逐条验）。

## 9. 三项候选：上了又撤回（2026-10-30 晚）

三项目标都是 1 ms 量级的真收益，但**全部因为画面副作用被撤回**。记在这里是为了
避免以后只看数字就把它们再打开。

| 候选 | 收益（实测） | 副作用（实机） | 处置 |
|---|---|---|---|
| **次级命中 mip+2** | **1.43 ms / 6.7%** | **室内、无光环境整体被抬亮**。mip 是下采样平均，方块贴图的平均色亮于其暗部像素；法线同样被平均，光照响应也变 | 默认回 **0**，改 opt-in（`ORION_SECONDARY_MIP_BIAS=1~3`） |
| **次级射线 OMM 2 态** | **0.00**（56 窗口，完美无收益） | 改变次级射线的 alpha 判定 ⇒ GI/反射的透光量变化（与 mip+2 一起关掉后室内明显变暗，说明它也有份） | 默认回 **4 态**；保留档 31 作对照 |
| **反射射线 tMax 96** | **1.85 ms** | **96 格外的反射回落天空色** ⇒ 室内（穿缝隙看向远处）与室外整体抬亮 | 回 **10000**；保留档 25/26/32 作探针 |

### 判据修正（这次踩的坑）

**“收益 > 1 ms” 不等于 “可以上线”**。这三项单看帧时间全部合格，但都是拿观感换的，
而亮度类副作用在静态帧时间上完全看不出来。以后对这类改动的要求：

1. 先过一道「**画面副作用**」检查，明确写出它会让哪里变亮/变暗/变糊；
2. 亮度边界由用户拍板（本项目：**画面不能比改动前更亮**）；
3. 只有零画面代价的项（如 emissive 无损跳过）才允许直接改默认值。

### 排查回顾（走了弯路，可供下次参考）

现象“室内变亮”，实际逐个排除了：`noDirectLightAmbient` 配置值 0.0107（真偏大，改成 0.0001
后游戏写回 0.0018）、自动曝光（关掉无变化）、PBR mip 放开（10-29 `d81612d`，关掉无变化）。
真正元凶是**今晚自己加的次级 mip+2**。

正确顺序应该是：先做一次「今天所有会改画面的改动」的**批量关闭对照**（一次 env 组合），
再逐个放开。这次是单点试了四轮才想到批量关。
